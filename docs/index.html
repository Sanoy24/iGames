iGames System Architecture

NestJS + MongoDB backend for Keno and 90-ball Bingo — audit-conscious, ledger-ready, and Telegram-integrated.

🎰

Keno Engine

Pick 1–12 numbers from 1–80. 20 numbers drawn per round. Configurable paytable with multiplier-based payouts up to 100,000×.

🎱

90-Ball Bingo

3×9 ticket grid, 15 numbers per ticket, numbers 1–90. Three prize tiers: one-line, two-lines, and full house.

💰

Ledger-First Wallet

Every balance mutation creates an immutable ledger entry in the same MongoDB transaction. Integer minor units, no floats.

🎲

Crypto RNG

All game draws use Node.js crypto.randomInt() with Fisher-Yates shuffle. Every draw is audit-logged with SHA-256 hashes.

🔐

Telegram Auth

Telegram Mini App initData validation with HMAC-SHA256. Maps to internal users and issues first-party JWTs.

💳

Telebirr Top-Ups

Manual receipt submission flow. Backend fetches, parses, and verifies receipts before crediting wallets.

Financial Safety Guarantees

⚠️
Non-negotiable: Wallet balance is never modified without a corresponding immutable ledger entry. Both operations always occur within the same MongoDB transaction.
  • Integer minor units — all money values are stored as integers (e.g., 100 = 1.00 credits). No floating-point arithmetic.
  • Idempotency keys — every ticket purchase and settlement carries a unique key. Replays return the original result without double-charging.
  • MongoDB replica set — required for multi-document ACID transactions across wallet + ledger + ticket documents.
