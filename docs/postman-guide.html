Postman Testing Guide

Step-by-step walkthrough to test the entire iGames API using Postman.

Prerequisites

  1. MongoDB running — docker compose up -d
  2. API running — npm run start:dev
  3. Base URL — http://localhost:3000
  4. NODE_ENV must be development (for dev seed endpoints)
💡
Tip: In Postman, create a Collection variable baseUrl = http://localhost:3000 and token = (empty). We'll populate the token in Step 1.

Step 1 — Get Auth Tokens (Dev Seed)

Since we can't simulate Telegram initData in Postman, use the dev seed endpoints to create test users:

Create an Admin User

POST http://localhost:3000/dev/seed/admin
Content-Type: application/json

{
  "displayName": "Test Admin",
  "roles": ["admin", "player"]
}

Response:

{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "eyJhbGciOi...",
  "tokenType": "Bearer",
  "expiresIn": 900,
  "user": {
    "id": "665f...",
    "displayName": "Test Admin",
    "roles": ["admin", "player"]
  }
}

📋 Copy the accessToken — you'll use this for all subsequent requests.

⚠️
In Postman, go to the Collection's Authorization tab → Type: Bearer Token → paste the accessToken. All requests in the collection will inherit it.

Create a Player User (optional second user)

POST http://localhost:3000/dev/seed/player
Content-Type: application/json

{
  "displayName": "Test Player"
}

Step 2 — Check Wallet (should be 0)

GET http://localhost:3000/wallet
Authorization: Bearer <accessToken>

Response shows availableMinor: 0 — the wallet is empty.

Step 3 — Fund the Wallet

Since Telebirr requires a real receipt, the easiest way to fund a test wallet is to create a bot user (which gets initial credits):

POST http://localhost:3000/admin/bots
Authorization: Bearer <admin-accessToken>
Content-Type: application/json

{
  "displayName": "Funded Player",
  "initialBalanceMinor": 500000,
  "ticketsPerRound": 0,
  "spotCount": 3
}

This creates a user with 500,000 credits. You can then seed that user as an admin to get their token:

POST http://localhost:3000/dev/seed/player
Content-Type: application/json

{ "displayName": "Funded Player" }

Use the returned accessToken for the player flow below.

Full Keno Flow

3a. Get Active Config

GET http://localhost:3000/keno/config

Returns the paytable, allowed spots, ticket price, number range.

3b. Buy a Keno Ticket

POST http://localhost:3000/keno/tickets
Authorization: Bearer <player-accessToken>
Content-Type: application/json
Idempotency-Key: test-keno-ticket-001

{
  "selectedNumbers": [3, 15, 27, 44, 68]
}

This debits the ticket price from the wallet and creates a pending ticket. Note the drawId in the response.

3c. List Your Tickets

GET http://localhost:3000/keno/tickets
Authorization: Bearer <player-accessToken>

3d. Execute the Draw (Admin)

POST http://localhost:3000/admin/keno/draws/execute-next
Authorization: Bearer <admin-accessToken>

This draws 20 numbers, evaluates all tickets, and settles winners. Response includes drawnNumbers and settlementSummary.

3e. Check Your Ticket Result

GET http://localhost:3000/keno/tickets/<ticketId>
Authorization: Bearer <player-accessToken>

Look at status ("won" or "lost"), matches, and payoutMinor.

3f. Check Updated Wallet

GET http://localhost:3000/wallet
Authorization: Bearer <player-accessToken>

If you won, availableMinor will have increased.

3g. View Ledger History

GET http://localhost:3000/wallet/ledger
Authorization: Bearer <player-accessToken>

Shows the stake debit and (if won) the win credit entries.

Full Bingo Flow

4a. Create a Bingo Room (Admin)

POST http://localhost:3000/admin/bingo/rooms
Authorization: Bearer <admin-accessToken>
Content-Type: application/json

{
  "name": "Test Room",
  "ticketPriceMinor": 100,
  "maxTickets": 50,
  "prizes": {
    "oneLineMinor": 5000,
    "twoLinesMinor": 15000,
    "fullHouseMinor": 50000
  }
}

Note the room id from the response.

4b. Buy Bingo Tickets (Player)

POST http://localhost:3000/bingo/rooms/<roomId>/tickets
Authorization: Bearer <player-accessToken>
Content-Type: application/json
Idempotency-Key: test-bingo-purchase-001

{
  "count": 3
}

Returns 3 generated tickets, each with a unique 3×9 grid.

4c. Draw Numbers One by One (Admin)

POST http://localhost:3000/admin/bingo/rooms/<roomId>/draw-next
Authorization: Bearer <admin-accessToken>

Call this repeatedly. Each call draws one number. Watch drawnNumbers grow and settledTiers fill in as tiers are achieved.

4d. Check Room State

GET http://localhost:3000/bingo/rooms/<roomId>/state

Shows drawn numbers, settled tiers, winners by tier, and settlement summary.

4e. Keep Drawing Until Complete

Keep calling draw-next until the room status becomes "completed" (full house achieved) or you've drawn all 90 numbers.

Other Useful Endpoints

List Draws

GET http://localhost:3000/keno/draws

Refresh Token

POST http://localhost:3000/auth/refresh
Content-Type: application/json

{ "refreshToken": "<your-refresh-token>" }

Cancel a Keno Draw (refunds all tickets)

POST http://localhost:3000/admin/keno/draws/<drawId>/cancel
Authorization: Bearer <admin-accessToken>

Cancel a Bingo Room (refunds all tickets)

POST http://localhost:3000/admin/bingo/rooms/<roomId>/cancel
Authorization: Bearer <admin-accessToken>

Postman Tips

  • Use Collection Variables for baseUrl, adminToken, playerToken, kenoDrawId, bingoRoomId.
  • Add a Test script on the seed requests to auto-save the token: 
    const res = pm.response.json();
pm.collectionVariables.set("adminToken", res.accessToken);
  • The Swagger UI at http://localhost:3000/docs also works for quick testing.
