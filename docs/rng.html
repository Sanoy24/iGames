RNG & Audit System

Cryptographically secure random number generation with full audit trail for every game draw.

Why Not Math.random()?

🚫
Non-negotiable rule: Math.random() is never used for game outcomes. It uses a PRNG (V8's xorshift128+) that is predictable and unsuitable for gambling applications. All game draws use Node.js crypto.randomInt().

Algorithm: Fisher-Yates Shuffle

The drawWithoutReplacement(min, max, count) method implements a partial Fisher-Yates shuffle:

drawWithoutReplacement(min, max, count):
  pool = [min, min+1, ..., max]          // All possible numbers
  
  for i = 0 to count-1:
    swapIndex = crypto.randomInt(i, pool.length)  // Cryptographic random
    swap(pool[i], pool[swapIndex])                // Fisher-Yates step
  
  return pool.slice(0, count)             // First 'count' elements

This guarantees:

  • Uniqueness — numbers are drawn without replacement (no duplicates).
  • Uniform distribution — every possible combination is equally likely.
  • Cryptographic security — uses crypto.randomInt() which sources entropy from the OS CSPRNG.
  • Efficiency — O(count) swaps, no rejection sampling needed.

Algorithm Version

Current version: crypto-random-int-without-replacement-v1

The version string is stored with every audit log so that if the algorithm is ever changed, historical draws can be attributed to the correct implementation.

Audit Log Schema

Every draw that specifies a gameType and gameReference creates an immutable audit record:

FieldDescription
gameType"keno" or "bingo"
gameReferenceDraw ID (Keno) or roomId:drawNumber (Bingo)
algorithmVersionAlgorithm identifier string
min, max, countDraw parameters
outputNumbersThe actual numbers that were drawn
inputHashSHA-256 of all draw input parameters (stable-stringified)
randomnessMaterialHashSHA-256 of 32 random bytes generated alongside the draw
metadataAdditional context (config version, room ID, etc.)

What the hashes prove

  • inputHash — proves the draw was requested with specific parameters. Can be recomputed from the draw request to verify integrity.
  • randomnessMaterialHash — proves that 32 bytes of cryptographic randomness were generated at the time of the draw. The raw material is not stored (to prevent reverse engineering), only the hash.
💡
The audit log is designed for internal verification, not public provable fairness. Future implementations could add commit-reveal schemes for public verification.

Input Validation

Before any draw executes, the RNG service validates:

  • min and max are safe integers, min >= 1, max >= min.
  • count is a positive safe integer and does not exceed the range size.
  • If gameType is provided, gameReference must also be provided (and vice versa).

Usage in Games

Keno

rngService.drawUniqueNumbers({
  min: 1, max: 80, count: 20,    // Standard Keno parameters
  gameType: 'keno',
  gameReference: drawId,
  metadata: { configVersion },
  session                          // Within the draw transaction
})

Bingo

// Each number is drawn individually from the remaining pool
rngService.drawUniqueNumbers({
  min: 1, max: remainingNumbers.length, count: 1,
  gameType: 'bingo',
  gameReference: `${roomId}:${drawNumber}`,
  metadata: { roomId, remainingNumbers },
  session
})
// The result indexes into the remaining numbers array

Bingo uses an indirect approach: it draws a random index into the array of remaining numbers, ensuring each number is drawn exactly once across the game.
