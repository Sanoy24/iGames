90-Ball Bingo

Room-based multiplayer bingo with three prize tiers: one-line, two-lines, and full house.

Game Rules

  • Ticket grid: 3 rows × 9 columns. Each row has exactly 5 numbers and 4 blanks (15 numbers total per ticket).
  • Number range: 1–90, drawn without replacement.
  • Column ranges: Col 0 = 1–9, Col 1 = 10–19, Col 2 = 20–29, … Col 7 = 70–79, Col 8 = 80–90.
  • Column rules: Each column has 1–3 numbers, sorted ascending top-to-bottom.
  • Players can buy 1–24 tickets per room in a single purchase.

Room Lifecycle

open
→
running
→
completed
  • open — accepting ticket purchases until maxTickets is reached or the game starts.
  • running — numbers are being drawn one at a time; tiers are settled as they are achieved.
  • completed — full house has been achieved; all remaining tickets marked as lost.
  • cancelled — room cancelled; all pending tickets refunded.

Prize Tiers

Each tier is settled exactly once per room. If multiple tickets achieve a tier on the same drawn number, the prize is split evenly among all winners.

How Players Win

Ticket Evaluation (BingoRulesService)

evaluateTicket(grid, drawnNumbers):
  drawn = Set(drawnNumbers)
  
  // Find which numbers on the ticket have been drawn
  markedNumbers = grid.flat().filter(n => n !== null && drawn.has(n))
  
  // Check which rows are complete (all 5 numbers drawn)
  completedLines = grid.filter(row =>
    row.filter(n => n !== null).every(n => drawn.has(n))
  )
  
  // Determine achieved tiers
  if completedLines >= 1 → 'one_line'
  if completedLines >= 2 → 'two_lines'  
  if completedLines === 3 → 'full_house'

Live Draw Flow

Each call to drawNextNumber(roomId):

  1. Pick one number — from the remaining undrawn numbers (1–90 minus already drawn), using the RNG service.
  2. Append to room — the drawn number is added to room.drawnNumbers[].
  3. Evaluate all tickets — every non-cancelled ticket is re-evaluated against the updated drawn numbers.
  4. Settle new tiers — if any unsettled tier now has qualifying tickets, the prize is split and credited to winners' wallets.
  5. Check for full house — if full_house is settled, the room status becomes completed and all remaining active tickets are marked as lost.
💡
Unlike Keno (where all 20 numbers are drawn at once), Bingo draws numbers one at a time. Each draw triggers a tier evaluation, making the game live and progressive.

Ticket Generation

The BingoRulesService.generateTicket() algorithm:

  1. Generate a mask — a 3×9 boolean grid where each row has exactly 5 true values (number positions). Retries up to 500 times until each column has 1–3 numbers.
  2. Fill numbers — for each column, draw the required count of unique numbers from the column's range using crypto.randomInt().
  3. Sort columns — numbers within each column are sorted ascending from top to bottom.
  4. Validate — asserts the ticket has exactly 15 numbers, 5 per row, 1–3 per column, all unique, and all in the correct column range.

Settlement Idempotency

Each tier settlement uses a unique idempotency key: bingo-settlement:{tier}:{ticketId}. This prevents double-crediting if the draw transaction is retried.

Room Cancellation & Refunds

When a room is cancelled, all pending tickets are refunded the full stake amount:

  • Each ticket: status → 'cancelled', settlementStatus → 'settled'.
  • Wallet credit with entryType: 'refund' and key bingo-refund:{ticketId}.
  • Completed rooms cannot be cancelled.
